ZBrush 分件碰撞检测插件

一键检查当前模型里所有子工具两两之间是否存在几何相交／穿透 —— 手办分件打印前的干涉自检。兼容 ZBrush 2022.0.5 与 2025.0.1，全中文界面。

① 第一步：双击运行 安装.bat
这套插件解决什么问题？
分件做完后，肉眼很难发现某个部件悄悄穿进了另一个部件。本插件自动把每个子工具两两比对，凡是发生相交／穿透的，都会把它们的名字对列出来，并写入检测记录，方便你逐个修正后再去 3D 打印。

一、安装（只需一次）

1先关闭 ZBrush，双击插件根目录的 安装.bat
新电脑不需要装 Python。安装程序和检测引擎都已打包成 exe（ZBCollisionInstaller.exe、dist/ZBCollisionEngine）。它会把引擎装到 C:\ZBCollision，并自动发现本机所有 ZBrush 安装目录（查注册表 + 扫描常见位置，要求目录里有 ZBrush.exe），把两个宏装进 ZStartup\Macros\Collision Check\。拷贝整个插件文件夹到另一台电脑，双击 安装.bat 即可。
2重启 ZBrush
安装后需要重启 ZBrush，宏才会出现在菜单里。
为什么引擎要装到 C:\ZBCollision？
ZBrush 脚本调用外部程序的官方机制要求路径不含空格，所以引擎独立放在无空格目录，宏只是引用它。默认 C:\ZBCollision，可用参数改：安装.bat --workdir D:\ZBCollision（同样不能有空格）。
ZBrush 装在非标准位置没被自动发现？ 用 安装.bat --zbrush-path "你的ZBrush安装目录" 显式指定（可重复指定多个）；或在 installer/install_config.json 里写 {"zbrush_paths": ["路径"]}；也可用环境变量 ZBRUSH_PATH。
安装后想先确认一切正常？
运行 python installer/自检.py，它会自动检查 Python 环境、引擎文件、两版宏是否装好、版本标记是否正确，并跑一次内置几何用例。若修改了代码，先跑 python tests/回归测试.py（55 项测试）确认没改坏。若实机运行出错，先跑自检能快速定位问题在哪一环。

二、使用（每次检测）

  1. 在 ZBrush 里打开你的模型，进入 Edit 编辑模式（按 T）。
  2. 确认工具里有 2 个以上子工具（SubTool）。
  3. 打开 Macro 宏面板，找到 Collision Check 文件夹，里面有两个按钮按需选择（按钮名用英文，是为了换到非中文系统的电脑上也不会乱码；鼠标悬停有中文提示）：
    • Quick Check（快速检测）：每对子工具只记录第一处相交点，速度最快，适合只判断"有没有相交"。
    • Full Check（完整检测）：列出每对子工具的全部相交点与坐标，较慢，适合需要查看所有相交细节、逐个定位的情况。
  4. 点击后，ZBrush 状态栏会实时显示"正在导出子工具 3/10"这样的进度，避免误以为卡住；导出完成后自动检测并弹窗。
  5. 稍等几秒，屏幕上会弹出一个独立的中文结果窗口，列出相交的子工具对和详细报告。完整模式下还会给出每对的全部相交点数量与坐标。结果由 Python 直接弹窗显示，不受 ZBrush 中文编码影响。

结果怎么看

提示含义建议
发现 N 处相交列出的子工具对存在穿透／相交按名字对逐个定位、调整位置或布尔修正
未发现任何相交所有子工具彼此分离可以进入后续打印／组装流程

三、检测记录在哪里

每次检测都会追加一行到 C:\ZBCollision\碰撞检测记录.txt，包含时间戳、ZBrush 版本、子工具数量、相交对、耗时，便于日后查证。工作目录里的 result.txt 是弹窗用的简明结论，完整报告.txt 是带坐标的详细报告，result.json 是结构化数据。

四、兼容性说明

本插件针对两个版本的 API 差异做了分支处理：

  • 导出按钮：优先用 File:Export，不存在时回退到 File:Export Selected。
  • 模式判断：用 IExists / IGet 检测按钮是否存在，两版通用。
  • 外部调用：宏逐个导出子工具后用 ShellExecute 启动检测程序；检测程序立即转入后台运行，ZBrush 不会被卡住，结果由独立的中文窗口显示。
  • 导出网格（逐个导出）：用 Tool:Export 把每个子工具单独导出成 sub_0.obj、sub_1.obj…，导出前用官方验证过的 SubToolGetStatus / SubToolSetStatus 隐藏其他子工具，导出后恢复原有可见状态。
    为什么逐个导出？因为 ZBrush 整体导出的 OBJ 用 g GroupNNNN 标记的是多边形组（Polygroup），不是子工具名，无法可靠区分分件。逐个导出能让每个文件精确对应一个子工具。
  • 中文界面实现：ZScript 编译器会剥离非 ASCII 字符，因此宏源码保持纯 ASCII，中文提示在运行时用 StrFromAsc 从 UTF-8 字节构造（与官方插件一致）。源码由 zscript/generate_macro.py 生成，日常使用无需关心。
  • 版本标记：IConfig 声明脚本所需最低版本，安装程序会按目标版本自动写入与官方一致的值（2025 版用 2025、2022 版用 2021）。
  • 检测引擎：纯 Python + NumPy，与 ZBrush 版本无关，天然跨版本。

五、常见问题

点了按钮什么窗口都没弹出？

检查工作目录 C:\ZBCollision\ 下是否生成了 error.txt——引擎把所有异常都写到这个文件里（因为结果窗口是无控制台运行的）。把它的内容发我即可定位。也确认该目录下有 run_detect.bat，没有就重新运行安装程序。

提示"结果不可信"？

说明某个子工具导出失败或不完整（子工具文件序号有缺口）。请确认处于 Edit 模式、工具可导出，然后重新检测。出现此提示时不要依据结果判断为安全。

提示“OBJ 导出失败”？

确认处于 Edit 模式，并且第一次导出时 ZBrush 弹出的 OBJ 导出选项面板点了确定。ZBrush 会记住导出设置，之后一般不再弹窗。

提示“子工具导出失败”？

确认处于 Edit 模式、工具是 PolyMesh3D，且工作目录 C:\ZBCollision 可写。逐个导出模式下，插件会在该目录生成 sub_0.obj、sub_1.obj…，可据此确认导出是否成功。

检测会不会改动我的模型？

不会。插件只做“导出 OBJ → 读取计算”，全程不修改 ZBrush 里的网格、遮罩或任何设置。

一个大模具太多面，检测慢怎么办？

引擎采用包围盒粗筛 + 命中即停策略，手办分件规模通常几秒内完成。如果单个部件高达数百万面，建议先用 Decimation Master 减面另存一份再检测。

精度提示：包含判定（一个部件完全在另一个内部）依赖网格近似封闭。若模型存在破面／开口，面面相交检测仍然可靠，但“完全包含”判定可能不准。手办分件绝大多数情况不受影响。

六、文件结构

ZBrush碰撞检测插件/ ├─ 安装.bat 一键安装入口（无需 Python） ├─ ZBCollisionInstaller.exe 打包好的安装程序（由 installer/install.py 生成） ├─ dist/ZBCollisionEngine/ 打包好的检测引擎 exe（无需 Python） ├─ installer/install.py 安装程序源码（自动发现 ZBrush 路径） ├─ installer/install_config.json 可选：非标准位置手动指定路径 ├─ installer/自检.py 安装自检工具（排查问题先跑它） ├─ zscript/out/Quick Check.TXT 快速检测宏（纯 ASCII，装到两个版本） ├─ zscript/out/Full Check.TXT 完整检测宏 ├─ zscript/generate_macro.py 宏生成器（改宏逻辑时用它重新生成） ├─ engine/ │ ├─ collision_engine.py 核心检测引擎（相交算法） │ ├─ result_window.py 中文结果窗口 │ ├─ detect_and_show.pyw 检测+弹窗主入口 │ ├─ run_detect.py 无界面批处理器（备用） │ ├─ run_detect.bat 备用启动器（无 exe 时用本机 Python） │ └─ launcher.pyw 独立图形界面（可选） ├─ tests/ 测试模型与验证脚本 │ ├─ 回归测试.py 55 项回归测试（改动后先跑它） │ ├─ 宏逻辑模拟.py 7 项宏链路模拟（补实机不可测维度） │ └─ fixtures/ 5 个几何测试模型 └─ docs/ 使用说明
